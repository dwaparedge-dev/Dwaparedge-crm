# Task Desk Implementation Plan (phases 0 to 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Tasks module with a founders' morning Desk (urgency sections and categories), follow-up timers, CRM-raised auto-tasks, and per-user permissions as the base for staff access.

**Architecture:** A new `src/features/tasks/` module mirrors the demo-requests feature (schema, service, route handlers, components). Pure modules (`permissions`, `policy`, `sections`) hold the rules and are unit-tested; services run in transactions and log to `activity_log`; the Desk computes urgency sections in TypeScript from one query so the badge and the screen share one definition. Auto-tasks are an idempotent sync (`POST /api/tasks/sync`) driven by SQL signal rules.

**Tech Stack:** Next.js 16 (App Router), React 19, MUI 9, PostgreSQL via `pg`, Zod 4, Vitest (unit in `tests/*.test.ts`, database-backed in `tests/integration/`), tsx for scripts.

**Spec:** `docs/superpowers/specs/2026-11-19-task-desk-design.md` (read it first; section numbers below refer to it). Phases 4 (reminders) and 5 (team rollout) are separate plans, written after phase 3 ships.

## Global Constraints

- Work on a branch `feat/task-desk`, not `main`. Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Next.js 16 differs from older versions (`AGENTS.md`): before writing routes or pages, skim the relevant guide in `node_modules/next/dist/docs/01-app`. Route handlers use `RouteContext<"/api/...">`, pages use `PageProps<"/...">` and `LayoutProps`; both types come from `npm run typecheck` (it runs `next typegen`). `params` and `searchParams` are Promises.
- All "today" logic is **Asia/Kolkata**: use `todayIST` and `daysUntil` from `src/lib/dates.ts`. Dates travel as `YYYY-MM-DD`; select them with `to_char(col, 'YYYY-MM-DD')`.
- Task statuses are fixed: `open`, `in_progress`, `waiting`, `done`, `cancelled`. **Active** = open, in_progress, waiting. Tasks are never deleted; cancel instead.
- Title 1 to 200 characters, description up to 5000, follow-up note up to 2000, waiting-on up to 200. Lists cap at 100 per page.
- Thresholds (one constants object, `THRESHOLDS` in `src/features/tasks/thresholds.ts`): renewals within **30** days, milestones within **7** days, **Stuck** after **3** follow-ups. Follow-up and snooze times must be in the future and at most **365** days out.
- Every mutating route: `assertSameOrigin(request)`, `requireUser()`, Zod parse, policy check, then a service call; errors go through `errorResponse`. Every mutation writes `activity_log` (`entity_type = 'task'`, `client_id` set when linked) in the same transaction. A task the actor may not see answers **404**, a forbidden action **403** with code `FORBIDDEN`.
- New tables go in `db/tables/tasks/` and in `db/schema.ts`; a change a sync cannot express (backfilling existing rows) goes in a numbered file in `db/migrations/` and the matching `db/tables` file is updated too.
- Integration tests need a Postgres in `DATABASE_URL` and run in a throwaway schema (`tests/integration/helpers.ts`). Unit: `npx vitest run tests/<file>.test.ts`. Integration: `npx vitest run --config vitest.integration.config.mts tests/integration/<file>`. Before every commit: `npm run check`.

## Review Focus

Inputs the spec implies but does not spell out. Each has a test in the task named in brackets.

1. **The IST midnight boundary.** At 00:15 IST the UTC date is still yesterday; a task due "today" must not read as overdue or as due tomorrow. [Task 7]
2. **Two people (or two tabs) acting on one task at once.** Two simultaneous Done clicks must produce one change and one history row; two simultaneous follow-ups must both count. [Tasks 9, 15]
3. **Follow-up and snooze times that are in the past, absurdly far, or malformed.** Refused with a clear message, task unchanged. [Tasks 5, 15]
4. **A category or priority hidden after tasks already use it.** Existing tasks keep showing it and stay editable; creating a new task with a hidden one is refused. [Task 9]
5. **Hostile text.** NUL and control characters, a 10,000-character title, and `%` or `_` typed into search. [Tasks 5, 9]
